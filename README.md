# GWS Livingart Tools

Internal company tools portal for GWS Livingart Pte Ltd. One login, one deployed app, multiple tools accessible from a shared dashboard.

Live: `https://hse-generator-production.up.railway.app` (repo name is historical — this started as the WHSE report generator and grew into a portal).

## Tools

### 1. WHSE Report Generator (`/whse/*`)
Upload a project's Method Statement (PDF/DOCX, or a Google Drive link) and Claude (Anthropic) generates a Risk Assessment (RA) and Safe Work Procedure (SWP), downloadable as Word or PDF. Supports feedback-driven regeneration, version history, and an "approve" flow that saves good outputs as few-shot examples for future generations. Existing RA/SWP example templates sync in from a Google Drive folder on startup.

### 2. Photo to Drive Bot (`/photobot`)
Status/reconnect dashboard for a **separate** WhatsApp→Drive photo bot (own repo: [`photo-to-drive`](https://github.com/gws-it/photo-to-drive), own Railway service). That bot watches WhatsApp groups and auto-uploads photos to Google Drive, organized by date and project. This page shows whether it's connected, and lets a non-technical user trigger a reconnect + scan a fresh QR code — no terminal/CLI needed. The backend proxies the bot's own token-protected HTTP API server-side, so the shared secret never reaches the browser.

### 3. Maintenance Report Generator (`/maintenance/*`)
Generates the two documents a maintenance visit produces: a **Maintenance Work Checklist** (prefilled, printed and hand-signed on site) and a **Maintenance Photo Report** (letterhead + dated photo grid). Pick a project, choose a date range, and it auto-finds that project's photos already uploaded by the Photo to Drive bot (matched by Drive folder naming). If a WhatsApp caption typo sent photos to the wrong folder, "Browse Drive manually" lets you navigate the same Drive tree by hand. Generated reports and downloads are **shared across all users**, not private to whoever generated them — history is a team-wide log with a "generated by" credit.

## Architecture

- **Backend**: FastAPI (`backend/`), SQLAlchemy + Postgres. Google OAuth login (domain-restricted to `@gwslivingart.com`) issuing a 7-day JWT.
- **Frontend**: React + Vite + Tailwind (`frontend/`), single-page app, client-side routing.
- **Deploy**: one Docker image (see `Dockerfile`) — frontend is built and copied into the backend's `static/` folder, so FastAPI serves both the API and the SPA from one process. Railway (`railway.toml`), one service (`hse-generator`) with `production` and `dev` environments.
- **Shared UI shell**: `frontend/src/tools.js` is the single source of truth for the tool list — shown on `/dashboard` and in the navbar's "Switch Tool" dropdown on every page.

## Local development

Backend:
```
cd backend
pip install -r requirements.txt
cp ../.env.example .env   # fill in values, see below
uvicorn main:app --reload
```

Frontend:
```
cd frontend
npm install
npm run dev   # proxies /api to localhost:8000, see vite.config.js
```

## Environment variables

See `.env.example` for the full list with descriptions. Summary:

| Var | Required for | Notes |
|---|---|---|
| `ANTHROPIC_API_KEY` | WHSE generator | Claude API key |
| `GOOGLE_CLIENT_ID` | Login | Google OAuth client, must allow the deployed origin(s) |
| `JWT_SECRET` | Login | Long random string — **rotating it logs everyone out** |
| `DATABASE_URL` | Everything | Postgres; Railway provides this automatically |
| `VITE_GOOGLE_CLIENT_ID` | Login (build-time) | Baked into the frontend at Docker build time |
| `PHOTOBOT_API_URL` / `PHOTOBOT_API_TOKEN` | Photo Bot tile | Must match `BOT_API_TOKEN` on the bot's own Railway service |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Template sync, Maintenance tool | Full service-account JSON. Reuses the Photo-to-Drive bot's own service account (it already owns every photo it uploaded) — see that repo's `~/.wa-drive-bot/service-account.json` |
| `GOOGLE_API_KEY` | Template sync (fallback) | Only works for public/link-shared files |
| `PHOTO_DRIVE_ROOT_FOLDER_ID` | Maintenance tool's manual Drive browser | Same value as `DRIVE_PARENT_FOLDER_ID` on the bot |

Google Cloud Console → APIs & Services → Credentials → the OAuth Client ID → **Authorized JavaScript origins** must include every domain this app is served from (production, and each Railway environment's own generated domain, e.g. `hse-generator-dev-xxxx.up.railway.app`).

## Database setup notes

- Tables are created automatically on startup (`database.init_db()` → `Base.metadata.create_all`) — there is **no migration tool**. Changing a model's columns on an already-deployed table requires a manual `ALTER TABLE` (see git history for examples — `client`/`address` columns were added this way).
- `backend/seed_projects.py` is a one-off script that imports the company's project masterlist into the `Project` table (used by the Maintenance tool's project picker). Re-run it manually (idempotent) if the masterlist gains new projects: `DATABASE_URL=<public proxy URL> python seed_projects.py`.

## Branching & deployment

- `main` = production, auto-deploys to the `production` Railway environment. **Never merge to `main` without explicit sign-off** — real users are on it.
- `dev` = active development, auto-deploys to the `dev` Railway environment (its own database — schema changes need the same manual migration treatment as production).
- Open a PR `dev → main` when a change is verified and ready to ship.
